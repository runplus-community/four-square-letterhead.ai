# FSL v1.7 - Concrete squares, adoption and visible routes

Based on the released v1.6 constitution at `d3e5e845a6356fdd961843371969ba0cd2238349`, the supplied v1.7 design draft and the subsequent decisions about optional iterations and R-01 routes. This is a new framework version; it does not modify the v1.6 release.

## Changes adopted for this version

- Concrete default SPEC / SYSTEM / AI / MEMORY; project FSL first inside SPEC; optional appendix, errata and amendments visible. Keep justified existing middle lanes, including FSL's own TEMPLATES / SKILL.
- Ownership follows purpose, not AI authorship. Consuming-project work stays in its own repository. AI inactivity is explicit, not a fabricated pass.
- Existing-system adoption through study/reverse engineering and a reviewed current-state baseline. Observed behavior is not automatically law. Historical and future iteration plans are optional; no history rewrite or forced rebuild.
- Stable project/contract-scoped R-01 route definitions with required touchpoints, boundary and outcome. Every run displays its full list before execution and records each point, unreached points included. Run context and connected evidence replace vague E2E badges.
- Explicit amendment adoption: a committed proposal has no automatic force. Record authority, exact delta, base clauses/version, effective scope and immutable reference; resolve overlaps and reassess affected evidence.
- Standalone 1P/2P/3P DOCX/PDF templates and an existing-system Django illustration. Source and verifier ship in the pack; run-sheet examples start NOT RUN.

## Existing text clarified, not silently contradicted

Article III now distinguishes new-repository main1 onboarding from prospective existing-repository adoption. POLICY-DEV-013 is scoped to recommend tiny E2E for new work while leaving existing-project iterations optional. LAW-TRACE-002 is clarified for authorized versioned revisions of the same obligation; unrelated obligations cannot recycle IDs. Article XII treats maintenance documents as optional alternatives and adds the adoption boundary. Original v1.6 files and reviewed release commits are preserved.

New clause IDs: POLICY-SQUARE-003; LAW-SPEC-001; LAW-OWN-001; LAW-REPO-001; LAW-ADOPT-001 / 002; POLICY-ROUTE-001; LAW-ROUTE-002; LAW-RUN-001; LAW-LIFE-006. Existing retired LAW-DEV-001 through LAW-DEV-004 remain retired and reserved.

## Deliberately not added

No new constitutional force vocabulary; no PATH/MODE/GROWTH schema; no full iteration plan; no YAML payload, route database, lifecycle registry or mandatory run-history ledger. The letterhead stays 1-3 pages; detailed method and evidence remain supporting artifacts.
