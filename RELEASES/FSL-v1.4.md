# FSL v1.4 — Development Strategy + Implementation References

FSL v1.4 preserves the v1.3 constitutional, traceability, proof and snapshot model and adds two deliberately compact capabilities.

## Development Strategy
- every material iteration declares a STRATEGY
- every material iteration declares a TOUCHPOINT SET
- START / MIDPOINT / END are declared where applicable
- expected evidence and exit condition are declared
- E2E / E2M / M2E / PARALLEL E2E / MEET-IN-THE-MIDDLE / INCREMENTAL E2E are canonical strategy tokens
- a declared touchpoint cannot be silently bypassed in an E2E claim
- component proof is not E2E proof
- tiny vertical completeness is preferred to large horizontal incompleteness

Development axiom: **TOUCH EVERYTHING REQUIRED; COMPLETE LITTLE; GROW WHAT IS PROVEN.**

## Implementation References
- TECHNOLOGY
- LIBRARY
- REFERENCE
- LINK

Recommended record: `CLASS / ITEM / FORCE / RELATION / PURPOSE / SOURCE`.

Relation continues to use REUSE / INHERIT / REFERENCE. Category does not imply normative force. Large dependency inventories remain outside the 1-3 page FSL letterhead.
