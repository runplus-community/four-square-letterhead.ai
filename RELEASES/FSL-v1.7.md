# FSL v1.7 - Concrete squares, adoption and visible routes

New framework release based on v1.6; prior release artifacts are not modified.

The default letterhead now shows SPEC / SYSTEM / AI / MEMORY, with the project's FSL document first inside SPEC and appendix/errata/amendments optional. Existing justified lane names are retained. Ownership follows artifact purpose rather than AI authorship.

Existing projects can adopt a reviewed current-state baseline through study or reverse engineering. Observed behavior is not automatically law. Historical and future iteration plans remain optional; adoption does not require rewriting history or rebuilding working systems.

R-01 identifies a stable scoped route. Every route run displays its declared touchpoints before execution and records every point, including NOT RUN, with connected evidence. Component passes and substituted integrations do not prove wider E2E claims. A proposal does not become an effective amendment merely by being committed.

The release payload includes real 1P/2P/3P PDF+DOCX templates, a Django 2P illustrative adoption sample, Constitution, Routes, Adoption, Lifecycle, Skill, four-item Checklist, Memory, Changelog, source generator, verifier, exact snapshot, validation, manifest and checksums. No font files, old nested release packs or YAML payload are included.

All four lane checks passed and all eight canonical PDF pages were visually reviewed before integration. Release assembly and post-extraction verification are separate recorded checks. The framework checks do not certify Django runtime, upstream adoption, or any consuming project.

Publication channel: public branch-scoped release, not a GitHub Releases-page publication. Exact artifact commit and ZIP checksum identify the final release view.
