# FSL v1.2 Recommended Development Checklist

This checklist is **RECOMMENDED**. It becomes binding only when a project LAW or CONTRACT explicitly requires an item.

## Constitution / SPEC
- [ ] Project identity, mission, boundary and source of truth are stated.
- [ ] Every binding statement uses MUST / MUST NOT (or exact SHALL aliases).
- [ ] SHOULD / SHOULD NOT items are clearly distinguishable from binding law.
- [ ] MAY is used only for genuinely optional behavior.
- [ ] Laws, contracts, policies and guardrails state their normative force.
- [ ] Every material MUST has an observable acceptance condition or evidence path.
- [ ] Conformance state is explicit: CONFORMANT / CONFORMANT WITH EXCEPTION / NON-CONFORMANT / NOT YET PROVEN.

## Four-Square lanes
- [ ] SPEC and MEMORY remain fixed.
- [ ] Middle lane A is selected from a durable project concern.
- [ ] Middle lane B is selected from a durable project concern.
- [ ] Middle-lane names are stable across the version lineage.
- [ ] MEMORY contains recall/learning material and does not silently create law.

## Development / agents
- [ ] Material work uses a checklist or equivalent visible plan.
- [ ] Agent responsibilities are defined when agents are used.
- [ ] Agents do not silently waive or reinterpret binding requirements.
- [ ] Discover -> Plan -> Execute -> Observe -> Verify -> Record is used where appropriate.
- [ ] Proven existing assets are evaluated before new core implementation.

## Exceptions / evidence
- [ ] Every binding exception names the clause, scope, owner and rationale.
- [ ] Evidence is attached or referenced.
- [ ] Review/expiry is recorded where applicable.
- [ ] Missing evidence is marked NOT YET PROVEN, not assumed successful.

## Document / release
- [ ] Four-Square Template v1.2 is visible on every page.
- [ ] Project/sample version is separately visible.
- [ ] Normative keywords are CAPITALIZED, bold and underlined in rendered pages.
- [ ] Page count is 1, 2 or 3 only.
- [ ] DOCX and PDF render without clipping, overlap or broken tables.
- [ ] Checksums are generated for the released file set.
- [ ] One version, four squares, all green before accepted release.
