# FSL v1.4 Recommended Checklist

## Development strategy
- [ ] Material iteration declares STRATEGY.
- [ ] Material iteration declares TOUCHPOINT SET.
- [ ] START / MIDPOINT / END are named where applicable.
- [ ] Every declared touchpoint is exercised meaningfully.
- [ ] Expected evidence is stated.
- [ ] Exit condition is stated.
- [ ] E2E is not claimed if a declared touchpoint is bypassed.
- [ ] Component-only proof is not labeled E2E.
- [ ] Tiny vertical completeness is preferred over large horizontal incompleteness.
- [ ] Next increment grows from a PROVEN path where practical.
- [ ] Parallel paths have explicit midpoint/integration contracts.

## Implementation references
- [ ] Important items are classified as TECHNOLOGY / LIBRARY / REFERENCE / LINK.
- [ ] Normative force is explicit when it matters.
- [ ] REUSE / INHERIT / REFERENCE relation is stated when project-boundary assumptions could leak.
- [ ] PURPOSE is stated.
- [ ] SOURCE points to the intended canonical location.
- [ ] Reference/reuse does not silently import unrelated law or assumptions.
- [ ] Large dependency inventories remain outside FSL.

## Existing FSL contract
- [ ] SPEC and MEMORY are fixed.
- [ ] Middle lanes are stable project-defined concerns.
- [ ] Clause IDs are stable.
- [ ] Proof uses CLAIM / SCOPE / ENVIRONMENT / EVIDENCE / RESULT.
- [ ] Template version and project version are separate.
- [ ] MEMORY may remember law; MEMORY cannot make law.
- [ ] Final document is 1, 2 or 3 pages only.
- [ ] One version, four squares, all green.
