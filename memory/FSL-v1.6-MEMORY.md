## Remember the simplification

One initial line: tiny input -> required touchpoints -> observable output -> prove -> grow.

No YAML iteration schema, no full future-iteration plan and no per-iteration ledger are required. Parallel E2E, E2M, M2E and meet-in-the-middle remain available. M is a named midpoint contract. Listing a touchpoint is not evidence; partial/component checks do not establish a bypassed real path.

Essential references only: item, intent/use, canonical source. Use an exact pin only when it matters. REUSE does not automatically INHERIT; REFERENCE does not adopt law. The authority remains in project SPEC.

Footer on every page: **FSL owns the method. The project owns the work.** Consuming-project artifacts and releases stay in that project's repository; the FSL repository stays reusable and reference-only.

## Remember the lifecycle

Draft -> Prove -> Release -> Appendix / Errata / Amendment -> Next Release.

Released SPEC stays frozen. APPENDIX clarifies or supports without changing intent. ERRATA corrects an error without changing intent. AMENDMENT changes normative intent and names the affected released version and clause IDs. The next release absorbs adopted errata/amendments into a new clean baseline. No lifecycle YAML or ledger is required.

Recommended names: `APPENDIX-A`, `ERRATA-001`, `AMENDMENT-001`.

Axiom: **Release is immutable. Clarify with appendix, correct with errata, change with amendment.**
