## Fixed model
SPEC and MEMORY are fixed. Two middle lanes are project-defined and remain stable across versions unless a reviewed migration changes them. `main1` is the immutable first-commit root; `main` is accepted integration.

## Constitutional language
FSL v1.2 distinguishes force explicitly:
- MUST / MUST NOT = binding law
- SHOULD / SHOULD NOT = strong guidance; deviation should record a reason
- MAY = permission
- EXCEPTION / WAIVER = explicit scoped departure from binding law

Normative words are CAPITALIZED, bold and underlined in rendered FSL pages. A binding requirement must never be silently weakened or bypassed.

Conformance states: CONFORMANT, CONFORMANT WITH EXCEPTION, NON-CONFORMANT, NOT YET PROVEN. Missing evidence is NOT YET PROVEN, not assumed success.

## Constitutional forms
ARTICLE, LAW, CONTRACT, POLICY, GUARDRAIL, RECOMMENDED PRACTICE, CHECKLIST. Binding force comes from the normative keyword, not the label alone.

## Development governance
Checklist-driven development is recommended: material work SHOULD use checklists; binding clauses SHOULD map to evidence. Agents MAY plan/execute/review/verify, but MUST NOT waive constitutional requirements without explicit authority.
