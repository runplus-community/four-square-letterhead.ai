## Remember the distinctions

SPEC defines, SYSTEM delivers, AI assists, MEMORY remembers. SPEC lists the completed project FSL first. Only SPEC and MEMORY are fixed; preserve justified middle-lane specializations. Ownership follows purpose, not the author or the word SKILL in a filename.

A route is the expected path; an iteration is a focused work-and-check loop; a run is one actual execution or review; evidence describes what happened. R-01 is a route, not an iteration or run counter. Compulsory I- numbering is gone; iterative development is not.

Route defines expected coverage; run records observed coverage. Squares own artifacts; routes cross only the artifacts needed for the claimed outcome. Every run displays its touchpoints and retains actual PASS, FAIL or NOT RUN results. These labels do not replace the conformance states.

For new projects, remember four recommended E2E goals: tiny complete path → useful behavior → boundary/recovery → intended-use rehearsal → grow. Repeat or split as needed. Existing projects adopt a reviewed present baseline and need not reconstruct these goals or development history.

An appendix explains; errata corrects without changing intent; an adopted amendment changes intent. A proposal is not approval. The released baseline stays unchanged. Approved intent is not execution evidence.

Use analogies and homologies to clarify, never to invent law. The route is the map; the run is the journey. English instructions can be a complete skill deliverable, but written instructions alone do not prove every future use.

MUST binds; SHOULD guides; MAY permits. Missing evidence stays NOT YET PROVEN; a known violation stays NON-CONFORMANT. A waiver does not turn NOT RUN into PASS. The four-square release check concerns the reviewed combination, not four unrelated success badges.

**MEMORY may remember law; MEMORY cannot make law.**
